# 赛题拆解单（problem brief）

拿到赛题之后、写代码之前的**第一份产物**。七张表填完，`results/schema.json`、`reports/tables/*.tpl.md`、`图件规划.md` 的骨架就已经定了，剩下的只是把数填进去。

`main.tex` 用 2025 数维杯秋季赛 A 题（离心作动器车体横向减振）做示例填好——换赛题时逐格替换内容，**表结构不要动**。

## 为什么先填表

赛题里"要交什么"是散的：题面正文有、三个小问里有、附件说明里还有。不先合并成一张表，就只能等算完再回头找"当初到底要哪个数"——那时模型已经按好看的标准挑过了，这就是**用结果倒推模型**。

那篇优秀论文正文 23 页、**0 张表**，结果全靠曲线和文字，评审无法核账；根子不在写作，在开局没有这张单子。

## 七张表

| 表 | 回答什么 | 填错的后果 |
|---|---|---|
| 表 1 题面清点 | 题面给了什么、没给什么 | "未给"栏空着 → 后面凭感觉补假设 |
| 表 2 场景 × 子问题 × 交付物 | 每问要交哪几样 | 少交一张图，最后一天才发现 |
| 表 3 参数表 | 每个数从哪来 | 自定参数混进题面参数却不标 → 结论不可复现 |
| 表 4 指标定义 | 定义式 / 量纲 / 单位 / 核验方式 | 量纲与单位对不上 → 全文数字作废 |
| 表 5 结果键 | `results.json` 里有哪些键、谁读 | 没人读的键留在库里 → 代码算一堆没人要的中间量 |
| 表 6 图件规划 | 每张图走哪条路线、读哪些键 | 没写 `reads` 的数据图 → 图上出现 schema 外的数 |
| 表 7 假设与风险 | 每条假设服务哪问、推翻哪个结论 | 假设写成套话 → 答辩一问就塌 |

三条硬判据（文末自检也印在 PDF 里）：

1. 参数表每个值都有来源标（题面给定 / 我方假设 / 推导）。
2. 结果键的"消费者"列不许空——空的就删。
3. 指标定义式的量纲 = 表里的单位 = 正文将写的单位，三处一致。

## 填完之后

```text
表 3 参数表      → code/utils.py 里的常量 + 论文参数表
表 5 结果键      → results/schema.json（键名 = results.json 里的路径）
表 5 + 表 2      → reports/tables/*.tpl.md（表格骨架，数值格只留 {{key}}）
表 6 图件规划    → reports/图件规划.md（数据图必须带 reads:）
表 7 假设        → 论文「假设」章，每条标注服务哪问
```

论文壳：

- 中文赛道 → `assets/templates/latex/default/`（ctexart，8 章）
- 数维杯 / MCM 式英文稿 → `assets/templates/latex/shuweicup/`（Summary Sheet + 6 章）

## 编译

```bash
cd assets/templates/problem && xelatex main.tex && xelatex main.tex
```

实测：4 页 / 0 error / 0 Overfull / 0 Underfull / 0 缺字（MiKTeX + xelatex，2026-11）。

> 圈码 ①②③④ 不要用：xeCJK 不覆盖 Enclosed Alphanumerics，会静默变成缺字。
> 写 `路线 1/2/3/4A/4B` 即可。
