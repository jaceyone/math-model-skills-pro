# G1 建模门禁（契约 + 三轮回质检）

## 〇、契约三件套（第 0 轮看这个，缺它后面全白做）

- [ ] `results/schema.json` 已落盘：每个键有 `label` / `unit`（无量纲写 `"-"`）/ `producer` / `consumers`
- [ ] 键名 = `results.json` 里的路径（至少两级、小写 snake_case），不同问题的同名指标带问题前缀
- [ ] 每个键至少有一个消费者：`table:<模板名>` / `figure:data_<图名>` / `paper:§N`
- [ ] 没有"没人读的键"：声明的每个键都能说出来谁用它
- [ ] `reports/tables/*.tpl.md` 已写：前置注释含 `table` / `caption` / `label`；数值格全是 `{{key}}`，**没有裸数字**
- [ ] 表里每个 `{{key}}` 都在 schema 里声明过；设计常数所在列表头带 `*`
- [ ] `reports/图件规划.md` 每张 `data_*` 都声明了 `reads:`，且 reads 里的键都在 schema 里
- [ ] 契约里没有出现具体数值（schema 只有元信息，表骨架只有占位符）
- [ ] `python scripts/check_contract.py --project 项目N` **退出码 0**（2 = 契约尚未建立）

## 一、报告内容完整性（第 1 轮看的）

- [ ] 子问题数量与题面一致
- [ ] 每个子问题有输入/已知条件
- [ ] 每个子问题有决策变量/预测对象/评价对象
- [ ] 每个子问题有目标函数或评价指标
- [ ] 每个子问题有约束条件
- [ ] 每个子问题有求解方法与停止条件（含复杂度或可行性说明）
- [ ] 每个子问题有输入输出与代码实现要点
- [ ] 每个子问题有结果校验方法（可机器执行：解析对照 / 守恒 / 极端情形 / 交叉验证，至少一种）
- [ ] 每个子问题有 3–6 条可核验得分点（用原词，不写态度描述），每条都挂得上结果键/图号/表号
- [ ] 每个子问题有证据链表（得分点 → 交付物 → 落点章节 → 验证方式）
- [ ] 每条 claim 写成「对象 + 方向」且判定口径明确；含「优于/显著/最优」的已规划 ≥2 类互补检验
- [ ] 预测类问题已建朴素/统计基线，未预设深度模型
- [ ] 假设敏感性预检已完成
- [ ] 数据理解（缺失/异常/单位）已写
- [ ] 图件规划覆盖四路（数据/机理/主图/流程），数据图张数与角色已定
- [ ] 代码任务清单已写
- [ ] 术语表格已写
- [ ] 符号表已写（`reports/symbols.md`）：一符一义、含单位、按首次出现排序，且与 S2 代码变量名一一对应；S4 的「符号说明 / Notation」章直接照抄，不重排、不改名
- [ ] 没有编造数据字段或数值

## 二、三轮回质检（缺一轮不算过）

留痕文件：`reports/QC_S1_ROUND.1.md`、`reports/QC_S1_ROUND.2.md`、`reports/QC_S1_ROUND.3.md`，
每份格式 `| # | 轮次 | 位置 | 问题 | 严重度 | 改法 | 状态 |`，末尾一行 `结论：PASS` 或 `结论：FAIL`。

| 轮次 | 检查维度 | 通过判据 |
|---|---|---|
| 第 1 轮 | **结构与覆盖**：上面的完整性清单 + 契约三件套在不在 + 得分点可核验性 + 图件四路不混 | 缺项 0；每个得分点都能指向一个数值/图/表 |
| 第 2 轮 | **一致性与冲突**：符号表 ↔ 公式 ↔ **schema 键名** ↔ 表骨架占位 ↔ 图件 reads ↔ 代码任务清单 同一套名字；假设之间不打架；初值/边界条件写全；**通篇没有"二选一"式表述**（"或者 A 或者 B"必须落成一条判据） | 符号零冲突；表里每个 `{{key}}` 都在 schema 里；每条假设都能在模型里找到落点；模糊表述 0 处 |
| 第 3 轮 | **可执行性与校验**：每个公式参数给全、量纲一致；**每个键说清生产脚本与校验方式**；每问有可机器执行的校验；灵敏度方案写清自变量、取值、判据 | 参数与单位齐全；每问 ≥1 条可执行校验；每个键都有 producer；灵敏度自变量明确 |

规则：

- 三份留痕的结论行都必须是 `结论：PASS`。
- 任一轮 `FAIL` → 回报告改 → 从**该轮**重跑（不要求重跑第 1 轮）。
- 质检期间只改 `reports/*.md`，**不许动 `code/`**；发现必须改模型时，先改报告与 `symbols.md`，再继续。

## 三、通过条件

- [ ] `python scripts/check_contract.py --project 项目N` **退出码 0**
- [ ] `reports/ANALYSIS_MODELING_REPORT.md` 已落盘，且能独立复现（别人只看它 + 契约就能写代码）

通过后进入 S2。**未过 G1（含契约）就写模型代码或出数据图 = 流程违规**，S4 一定会出现模型、结果、论文三张皮。
