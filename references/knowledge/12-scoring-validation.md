# 12 · 得分点驱动与验证契约

> 本文件规定得分点怎么立、怎么兑现、怎么核账。**S1 立规矩，S2 兑现，S4 核账。**

## 一、主干硬约束

1. 未跑通、`results/` 无真实数值 → **禁止**写定量结论、禁止编造结果表。
2. 正文/摘要里每个数字都要能对上 `results/results.json`（键先在 `results/schema.json` 立过），表格用 `fill_tables.py` 从同一份 JSON 生成；禁止凭记忆写数。
3. 验收 = 证据完整且前后对应：脚本跑通有图有数只是基线；数值精度、重复次数、验证强度要足以支撑 claim。
4. 「模型的建立」必须有推导链（变量 → 关系 → 目标/约束），禁止只有口号公式。
5. **预测模型按证据选，不预设深度模型**：先建朴素/统计基线，再依样本量、序列长度、季节性、非线性、外生变量、预测跨度、可解释性要求，在统计时序 / 状态空间 / 树模型 / 深度序列 / 机理混合模型中选择。LSTM/GRU 只有在数据量与验证设计足够、且公平验证显示适配时才采用；小样本强上深度模型是减分项。
6. 章节按竞赛骨架；各问在「五、模型的建立与求解」下编号 5.1 / 5.2 …；每问有小结。

## 二、得分点驱动（评委按维度找分，找不到 = 没做）

1. **立即可核验**：每条 `score_points` 写成可交付物 ——「给出完整目标函数 + 3 类约束并报告 gap」优于「认真分析」；带上方法名/指标名/图表类型的**专业术语原词**。**立点时就挂上结果键**（`problem2.reduction_pct`）或图表 id（`tab:q2_index` / `data_q2_response`）：挂不上的得分点，S2 无从兑现，S4 无从落点。
2. **求解阶段核账**：收工前逐条对 `score_points` —— 要的数值在 `results` 里吗？要的画了且角色命名对吗？要的对比/扰动真跑了吗？有缺口立即补做重跑。**求解阶段是补证据唯一合法时机**，写作阶段再发现只能承认局限。
3. **按题意交付，不机械凑七件套**：每问必须有方法/模型定义 + 可核验公式或规则 + 真实数值 + 适用验证。算法块只用于确有迭代/优化的题；`comparison` 只在存在合理基线或比较性 claim 时要求；`sensitivity` 只对关键参数或稳健性 claim 要求。为凑角色造无意义产物是负分。
4. **写作阶段**：每条得分点在正文有一段可指认的论述 + 一个支撑物（公式号 / 图号 / 表号），**沿用原词**，不改写成同义词；关键结果在摘要—正文—模型评价三处呼应。
5. **维度落点**：假设→「模型假设」章；符号→「符号说明」章；检验/灵敏度→独立一章；创新→摘要末与「模型评价」。任一维度全文无处可寻即失分。
6. 做不到就在「模型评价」如实写局限与改进方向；**空写一句糊弄比承认局限扣得更多**，严禁为凑分编数字。

## 三、数据与证据

1. 数据优先级：附件/题面 → 公开数据（GitHub 等，只下数据文件，写 `data/data_source.json`：mode/url/commit/license/字段单位）→ 固定种子（42）模拟数据（**必须标注「模拟/合成」**，严禁冒充真实观测）。
2. `claims` 须可检验：比较对象 + 方向；含「显著」类主张必须绑定统计检验。
3. 判定口径：`supported`（有数值且方向一致）/ `insufficient`（缺数据、缺检验、缺对照）/ `contradicted`（方向矛盾）。
4. 每问跑通后立刻写 `reports/journal_problemN.md`：**关键数值 / 图表结论 / 结果表格 / 结论核对 / 遗留**。图结论逐张写清可见数字与证明点；表摘录主数字；与 claim、`results.json` 前后对应。写论文时优先摘抄纪要，不凭记忆编数字。

## 四、灵敏度与模型检验（空话不得分，没重跑 = 没做）

1. **硬触发**：得分点含灵敏度/对比/误差/消融，或结论含优于/最优/推荐，或进入「模型检验」章 → 必须交付真实重跑证据。
2. **强度按风险与主张决定**：含「优于/显著/最优」、随机算法或关键决策建议的问题至少做 2 类互补检验；简单确定性计算做 1 类最相关检验，或说明其余为何不适用。候选类型：参数灵敏度、规模扫描、基线/消融、机制替换、多情景、误差残差、求解质量（gap）。
3. **默认做法（没有更好方案时照此办）**：单参数扰动取 ±10% / ±20%（或该参数的合理区间上下界），报「参数变化 → 指标变化 → 结论是否改变」；多参数按影响力排序用 Tornado 图（一张图顶一张表）。按题型选扰动对象：优化类改约束右端项与目标系数，看最优解是否质变；预测类改初始条件与关键假设，看预测曲线漂移幅度；评价类改权重与指标口径，看排序是否翻转。
4. **落盘**：扰动参数名、水平、指标、取值写入 `results.json`（建议 `sensitivity` 对象）；图用角色名 `problemN_sensitivity` / `problemN_comparison`。
5. **禁止编数**：灵敏度百分比、提升幅度、p 值、gap 只能来自本次运行；禁止「约 ±8%」「较为稳健」这类无支撑表述。
6. **载体按数据形态选**：密采样响应曲线用图；离散扰动（两三个水平）画出来只是几根光柱 → 改三线表，逐行「参数由 a→b、指标变化 z%、结论是否改变」；只有一两条就写成句子。**表里每行都得有数**，只写「稳健/影响不大」的汇总表不要出现。
7. **写作位置**：对照/消融放「结果与分析」一张图或一张表；检验节只点「见表/图 X.Y，指标由 A→B」，禁止「验什么→怎么验→数值→结论」四段念数。结论给结构性洞察（拐点/临界/饱和）+「临界 + 代价」句式。
8. 补证据窗口在 S2；S4 发现缺口只能承认局限或回 S2 重跑，不得口头补数据。

## 五、学术分寸（结论强度与证据匹配）

- 启发式/近似算法的解称「高质量近优解 / 非支配近优解」，不称「全局最优」（精确求解已证最优的除外，并报 gap）。
- 依赖给定数据的结论加限定「仅适用于本题给定数据条件」。
- 小样本/合成/仿真实验只下限定性结论（「在本文测试场景下」）。
- 约束不绑定、Pareto 前沿退化、指标反直觉等现象主动解释成因（数据条件/口径），不回避。
- 判据不满足就如实说不满足，并分析原因；不把「未达标」写成「基本达标」。
