# S1 建模分析（建模手）

## 目标

把题面拆成可实现的子问题，给出模型、公式、算法、输入输出、校验方法和图件规划。**产出的是 md 文件，S2 只是把这份 md 翻译成代码**——所以这一阶段的质量决定后面全部环节，宁可多花时间。

## 契约先行（本阶段的铁律）

顺序不能反：**先拆题立得分点 → 再写契约三件套 → 才写模型与公式 → 质检 → 才允许写代码**。

- 「契约三件套」= `results/schema.json`（结果键）+ `reports/tables/*.tpl.md`（表格骨架）+ `图件规划.md`（数据图 `reads:`）。它们回答的是"这道题要交哪几个数、每个数长什么样、谁读它"，比公式更接近编码现场。
- 三件套里的每个键，都必须能在 `ANALYSIS_MODELING_REPORT.md` 找到对应的定义与口径（符号、单位、统计区间、初值）。**报告定义模型，契约定义交付**：两者互相兜底，缺一边就会在 S4 对不上。
- **禁止"先跑个数出来再补报告/补表"**：那样写出来的报告是对结果的追认，表是照着结果拼的，S4 一定会出现模型、结果、论文三张皮。

> 为什么表要在写模型前定：一张表的列名和行标签，就是"这问要交什么"的精确写法。先把它写出来，模型推导只有两个方向——把空格填上，或发现空格问错了。先跑代码再想摆什么，方向就只剩一个：迁就已有的数。

## 输入

- `input/` 中的题面与附件
- `plan.md`
- `references/knowledge/` 对应章节（按需读取，不整库加载）
- `references/knowledge/12-scoring-validation.md`（**得分点怎么立、证据怎么算够**）
- `references/knowledge/13-writing-injection.md`（摘要/推导口径，决定分析报告的语汇）
- `references/algorithms/`（按题型选算法）
- `tools/paper-search`（需要文献时）

## 步骤

### 1. 子问题拆解

只把题面明确编号的顶层问题当作子问题。每个子问题写：

- 输入数据与已知条件；
- 决策变量 / 预测对象 / 评价对象；
- 目标函数或评价指标；
- 约束条件；
- 与其他子问题的依赖；
- **得分点（`score_points`）**：3–6 条可核验交付物，用题目与专业术语原词（「给出完整目标函数与 3 类约束并报告 gap」优于「认真分析」）；每条现在就要能指向一个结果键、一张表或一张图——挂在空处的得分点在 S4 无处落点。

### 2. 契约三件套（写模型之前必须落盘）

#### ① `results/schema.json`：结果键清单

把"论文里要出现的每个数"先立成键，四件事一次说清：**含义、单位、谁产出、谁读它**。格式与字段见 `references/contracts/results-schema.md`。

```json
{
  "version": 1,
  "keys": {
    "problem2.control_index": {
      "label": "双通道控制后振动指标",
      "unit": "m^2 s^-3",
      "digits": 2,
      "producer": "code/problem2.py",
      "consumers": ["table:q2_index", "figure:data_p2_response", "paper:§5.3"]
    }
  }
}
```

写这张表的方法不是"猜代码会算出什么"，而是**从论文倒推**：摘要要几个数？每一问的结论句要几个数？灵敏度节、鲁棒性节、约束校验各要几个数？逐个列出来，凑不出来的说明那一节的论证还没想清楚。

#### ② `reports/tables/*.tpl.md`：表格骨架

列名、单位、行标签写死；数值格一律 `{{key}}`，**不许出现裸数字**（题面给定的设计常数走列头 `*` 声明）。写法与生成链见 `references/contracts/table-template.md`：`reports/tables/x.tpl.md` →（`fill_tables.py`）→ `results/tables/x.tex` → 论文 `\input`。

```markdown
<!-- table: q2_index | caption: 场景 2 指标对照 | label: tab:q2_index | format: auto -->
| 情形 | 指标 $I_h$ | 降幅 |
|---|---|---|
| 被动 | {{problem2.passive_index:.2f}} | — |
| 双通道 | {{problem2.control_index:.2f}} | {{problem2.reduction_pct:pct}} |
```

每张表都要能回答"评委看这张表能得出什么结论"；得不出结论的表，删掉。

#### ③ `reports/图件规划.md`：图件清单 + 数据图 `reads:`

四路分工（数据/机理/主图/流程）按 `references/knowledge/05-figures.md` 的判据分；**每张 `data_*` 数据图必须声明 `reads:` 读了哪些键**，S2 画图时按这个清单取值，不许临时翻 `results.json` 找好看的数字。

| 编号 | 路线 | 文件名 | 用途 | 章节 | 读取键 |
|---|---|---|---|---|---|
| ①-1 | 数据图 | `data_q2_response` | 被动 vs 控制 | §5 | `reads: problem2.passive_index, problem2.control_index` |
| ②-1 | 机理图 | `mech_actuator` | 力矢量合成 | §3 | — |

张数档位（国赛数据图 4–6、美赛 3–5、华为杯 8–10）见 `05-figures.md`；画法契约见 `14-figure-contract.md`，本阶段只定「画什么、证明什么、读哪些键」，不写绘图代码。

#### ④ 报告里的「交付清单」小节

分析报告不复制表格本体（表格在 `reports/tables/` 维护，复制一份就有两处要改），但必须有一节把交付物点名：

```markdown
## 交付清单

| 类型 | id | 内容 | 读哪些键 |
|---|---|---|---|
| 表 | `tab:q2_index` | 被动/双通道指标对照 | problem2.passive_index, problem2.control_index, problem2.reduction_pct |
| 图 | `data_q2_response` | 位移与加速度时程 | problem2.passive_index, problem2.control_index |
| 正文 | §5.3 | 降幅结论句 | problem2.reduction_pct |
```

这一节是报告与契约的接口：`check_contract.py` 会反向核对"schema 里的每个键都能在报告里找到定义"，找不到就说明你声明了一个报告没论证过的数。

### 3. 假设敏感性预检

列出关键歧义，每种歧义至少给两种解释，用简单验算或逻辑递进判断。写入：

```markdown
## 假设敏感性预检

### 模糊表述及解释
### 快速验算与递进性检查
### 最终采用的解释
### 绘制的图像和对比表格
```

如果某个假设会让后续问题的新增条件没有边际效果，回头调整解释。

### 4. 数据理解

对每份附件写：行列规模、字段含义、缺失/异常/重复/单位不一致、可直接使用的变量、需要派生的指标。

### 5. 模型与算法

每个子问题至少包含：

- 问题目标；
- 符号与变量；
- 模型假设；
- 目标函数；
- 约束条件；
- 求解方法（核心步骤、停止条件、复杂度/可行性）；
- 输入输出；
- 代码实现要点；
- 结果校验方法；
- 灵敏度分析方案。

模型选择参考 `references/knowledge/02-model-selection.md`，题型防错参考 `03-pitfalls-by-type.md`。

**预测类特别条款**：不预设 LSTM/GRU。先建朴素/统计基线，再依样本量、序列长度、季节性、非线性、外生变量、预测跨度与可解释性要求在统计时序 / 状态空间 / 树模型 / 深度序列 / 机理混合模型之间选；小样本不得为「高级」强上深度模型（`12-scoring-validation.md` 第一节第 5 条）。

### 6. 证据链设计（S2 照着做，S4 照着核）

为每个子问题写清三件东西：

```markdown
| 得分点 | 交付物（数值/图/表） | 落在哪一节 | 验证方式 | 现状 |
|---|---|---|---|---|
| 给出酒精对评分的边际效应 | β 系数 + 95% CI + 表 5.3 | 5.1.4 | t 检验 + VIF | 待跑 |
```

- **claims**：每条主张写成可检验形式（比较对象 + 方向），标注 `supported / insufficient / contradicted` 的判定口径；
- **journal 计划**：S2 每跑通一问就写 `reports/journal_problemN.md`（关键数值 / 图表结论 / 结果表格 / 结论核对 / 遗留）；
- **检验强度**：含「优于/显著/最优/推荐」的问至少 2 类互补检验，简单确定性计算 1 类并说明其余为何不适用。

细节见 `12-scoring-validation.md` 第二至四节。

### 7. 代码任务清单（= 谁来填哪些键）

表骨架定完，代码任务清单基本就是"键 → 生产者"的反向清单：每个 `producer` 脚本负责哪几个键、按什么顺序跑、每个键用什么方式校验。

```markdown
## 代码实现任务清单

| 任务 | 输入 | 产出键（schema 键名） | 方法 | 校验 |
|---|---|---|---|---|
| problem2.py | input/data.xlsx | `problem2.passive_index`, `problem2.control_index`, `problem2.reduction_pct` | 双通道设计 + 时域仿真 | 与解析固有频率对照、约束回代 |
```

清单里出现、schema 里没有的键，当场补进 schema；schema 里有、清单里没有生产者的键，当场删或补任务。

## 必须产出

- `results/schema.json`（结果键清单：label / unit / digits / producer / consumers）
- `reports/tables/*.tpl.md`（至少覆盖每问的核心指标表；数值格只许 `{{key}}`）
- `reports/ANALYSIS_MODELING_REPORT.md`（含每问的得分点表与证据链表）
- `reports/symbols.md`（符号表：符号 / 含义 / 单位 / 首次出现位置；S1 定稿，S2 变量名与 S4 符号表都照抄，不许各写一套）
- `reports/术语表格.md`（中英文对照；下游：S2 变量命名与注释、S4 中英稿术语统一）
- `reports/图件规划.md`（四路分工；数据图行带 `reads:`）
- `reports/SCORE_MAP.md`（得分点表；S2 补证据列、S4 补落点列）
- `reports/QC_S1_ROUND.1.md`、`.2.md`、`.3.md`（三轮回质检的留痕，见下）

## 三轮回质检（S1 之后、S2 之前，必须做完）

**这是全流程唯一"多轮"的门禁。** 一轮看结构、二轮看一致性、三轮看可执行性；每轮把问题清单写进 `reports/QC_S1_ROUND.N.md`（`| # | 轮次 | 位置 | 问题 | 严重度 | 改法 | 状态 |`），改完再进下一轮。

| 轮次 | 看什么 | 通过的判据 |
|---|---|---|
| 第 1 轮：结构与覆盖 | 每问七件套齐不齐（目标/变量/假设/目标函数与约束/算法/输入输出/校验）；**契约三件套在不在**（schema 键、表骨架、图件 reads）；得分点是否可核验 | 缺项为 0；每个得分点都能指向一个结果键/图/表 |
| 第 2 轮：一致性与冲突 | 符号表 ↔ 报告公式 ↔ **schema 键名** ↔ 表骨架占位 ↔ 图件 reads ↔ 代码任务清单 是否同一套名字；假设之间是否互相打架；边界条件与初值有没有写 | 符号零冲突；**表里每个 `{{key}}` 都在 schema 里**；每条假设都能在模型里找到落点；无"二选一"式模糊表述 |
| 第 3 轮：可执行性与校验 | 公式能不能真算（参数是否给全、量纲是否一致）；**每个键是否说清了生产脚本与校验方式**；每问是否都有可执行的校验方法（解析对照/守恒/极端情形）；灵敏度方案是否写清自变量与判据 | 每个公式的参数与单位齐全；每问至少 1 条可机器执行的校验；每个键都有 producer |

三份留痕文件的最后一行必须是 `结论：PASS` 才算过门禁；任一轮 `FAIL` 就回到报告改，改完从**该轮**重跑（不要求重跑第 1 轮）。

## 边界

- 不写代码、不跑数据、不生成图。
- 不写论文正文。
- 不编造数据字段和数值；得分点不写态度描述。
- **不在契约里写具体数值**：schema 只有元信息，表骨架只有占位符；数值是 S2 的产物，S1 写进来就是把结果提前编好了。

## 门禁

```bash
python <skill-root>/scripts/check_contract.py --project 项目N   # 退出码 0 才算过（2 = 契约还没建）
```

通过 `references/checklists/G1-analysis.md`（**含三轮回质检**）后进入 S2。
